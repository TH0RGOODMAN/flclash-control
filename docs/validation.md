# 0.1.0 验收说明

2026-11-16，在 Windows x64、FlClash 0.8.93、Flutter 3.41.9 环境完成本机验收。普通上游程序没有此控制桥，须安装与引擎匹配的集成构建。

## 结果

- 客户端 28 项测试通过；覆盖 DPAPI 认证、请求映射、代理环境隔离、重定向拒绝、超时和错误脱敏。
- Dart 34 项测试通过：上游控制器 24 项、缺失原生响应 6 项、配置与监听完成/失败时序 4 项。变更文件静态分析无问题。
- 六个原文件的集成补丁可从固定上游提交重建，重建内容比对通过。
- 已安装桥支持九个 MCP 工具，真实 stdio 握手、工具列举与调用通过。
- TUN、系统代理、global/direct/rule 模式往返与保存状态一致。系统代理开关已核对 Windows 实际代理设置，TUN 已核对内核设置、Meta Tunnel 网卡和路由。
- 停用代理后混合端口不再监听；GUI 和桥保持运行。再次启动恢复监听和 TUN。
- 运行与停止状态下的原生重连均保持原状态。运行态重连后内核由 Helper 服务托管，外网访问正常。
- 正常退出观察到 GUI 进程结束；重开后模式和系统代理偏好保留。autoRun 关闭时重开保持停止，调用 start 后恢复网络。
- 系统代理关闭、TUN 开启时，无显式代理的 HTTPS 请求得到 Google 204、YouTube 200、百度 200，证书验证开启。
- 未认证、错误认证、浏览器 Origin 请求被拒绝；意外参数被拒绝。

## 已修复的可靠性问题

控制桥保留 TUN 临时授权状态的订阅，避免窗口隐藏时 Riverpod 自动释放状态导致误报。原生 IPC 缺失响应不会被当作成功。

控制用的严格启动/重连路径等待配置和监听操作完成并观察双方失败，传播授权、初始化和配置错误。失败时清理残留运行计时。普通 GUI 使用原有的错误展示方式。

状态查询绕过变更队列，权限等待时仍可读取 `operation_pending`、`active_action`、`pending_commands`。待完成期间的快照不证明操作成功；客户端超时也不等于操作已经取消。

## 验收边界

这是单机、固定版本验收，不代表跨版本兼容、长期稳定或安全审计已经完成。拒绝 UAC 和辅助服务不可用的完整现场恢复未实际演练；相关缺失响应和并发失败有专项测试。

早期独立内核托管实验未部署，不属于支持方式。本项目不是 FlClash 官方发行版。分发集成 GUI 时须保留上游 GPL 许可证、声明和对应源码。
